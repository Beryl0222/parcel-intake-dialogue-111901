# 园区选址咨询中的复合业态与待核事实

utterances 按数组顺序记录咨询发言。places 的 uses 以楼层为键，aliases 保存现场口称。rules 的 id 是清单引用号，text 是清单原文。

资料保存在 `data/inputs.json`，采用 UTF-8 JSON。记录、人员、地点和业务编号均为合成内容。

运行环境为 Node.js 22.23.4，资料工具和测试使用 Node.js 标准库。

```sh
npm run inspect:data
npm test
```

`inspect:data` 读取资料并列出记录数。测试核对该批资料的字段和引用完整性。

## 窗口咨询演练

`src/` 下实现窗口咨询流程：经办人连续补充计划，系统分辨业态、空间、规模、
实施阶段与备选/选定，对照清单给出可查询的答复。

```sh
npm run consult              # 按 data/inputs.json 的发言批量演练并列出答复档案
npm run consult -- repl      # 先跑资料发言，再逐句输入继续演练
npm run consult -- answers   # 只列答复档案（仍可引用 / 必须收回）
npm run consult -- answer A2 # 查看某条答复当时的选项、事实及依据（含原句）
```

交互模式下可用 `:state`（当前方案）、`:answers`（答复档案）、
`:answer A1`（单条依据）、`:rules`（清单编译结果）、`:quit`。

### 处理约定

- **每条解释附原句**：理解出的地点、楼层、业态、规模、阶段都标注所依据的发言原句。
- **多方案并行**：「南楼备选、北楼照旧」只改相应方案；「二楼还没定」清掉该方案已确认的楼层。
- **不替经办人选定**：简称指多栋楼、单位缺失会跨过清单界限、否定范围不清时，
  先给出现有事实仍成立的结论，再问真正能区分结论的问题。
- **明确不可行立即指出**：某项经营在某处确定被禁止时当场说明并附可尝试的调整，
  其他阶段和业态可继续咨询。
- **清单分三类**：通用要求、楼栋条目（places）、定向例外。例外只解除它明确引用的限制，
  且仅在适用条件全部确认时；条件未明则该经营不能确认。
- **手续与投运分开**：免办某道手续（如 P2）不等于准许投运；投运前提（如 P3 隔声验收）
  是另一类判断，确实可行时一并列出还要做什么。
- **答复可追溯**：每条答复按当时的选项、事实及依据存档。方案变更后，
  依据仍成立的答复仍可引用，依据失效的必须收回并说明是哪条事实变了；
  改回原选项后，早先答复恢复可引用。假设情形（「要是……吗」）只给条件答复，不纳入方案。
